# Odex decision log

Decisions made without asking, with the reasons. Newest last. Each one is referenced from code comments as `D-NNN` where that helps.

| ID | Decision | Why |
|---|---|---|
| D-001 | The repo root *is* the `odex/` tree from PROMPT §2: `engine/`, `desktop/`, `presets/`, `docs/`. Two engine crates were added beyond the list: `cli` (the `odex-engine` binary) and `mock-vllm` (test server + binary). | Keeps the binary separate from the libraries, and lets tests and Playwright share one mock. |
| D-002 | The protocol is JSON-RPC 2.0, **with** the `"jsonrpc":"2.0"` field (upstream omits it), newline-delimited on stdio. It exchanges an explicit semver `protocolVersion` in `initialize` instead of experimental gating. | Standard JSON-RPC tooling works, and version mismatches fail clearly. |
| D-003 | Streaming deltas are one notification, `item/delta`, with a typed `delta` union (agentMessage, reasoning, commandOutput, toolArguments, progress), instead of one method per delta type. Approvals are one server request, `approval/request`, with a typed `kind`. | The UI gets one switch statement and the TS types stay simpler. Parity mapping is in PARITY.md §C. |
| D-004 | Crate versions are pinned to APIs we know well: reqwest 0.12, toml 0.8, ts-rs 10, axum 0.7, rusqlite 0.32 (bundled, FTS5), windows 0.58, portable-pty 0.8. | They are mature and the Rust 1.97 toolchain builds them. Upgrading is mechanical later. |
| D-005 | TypeScript is generated by ts-rs (`odex-engine generate-ts`). A post-pass rewrites `x: T \| null` to `x?: T \| null`. | One source of truth, and TS matches serde's tolerance for missing `Option` fields without annotating hundreds of fields. |
| D-006 | The config schema structs live in the protocol crate (snake_case TOML), so the same types drive `config/read` and the settings UI. Layering: defaults → user `~/.odex/config.toml` → active profile → trusted project `.odex/config.toml`. Projects can't set providers, sandbox, trust, approval policy or full access. | A cloned repo must not be able to redirect your endpoints or loosen your sandbox. |
| D-007 | Model keys can be a `[models.<key>]` entry, `provider:served-model-id`, or a bare served id found on any endpoint. Roles fall back to `main`, then to the first discovered chat model. | Odex works with zero config against a running vLLM, and explicit config still wins. |
| D-008 | Structured outputs use `response_format: {type: json_schema}` by default. `guided_json` is kept only as an explicit opt-in. | vLLM removed `guided_*` in v0.12 and **silently ignores** it now (verified in docs/research/vllm-flags.md). `response_format` works on every version. |
| D-009 | Reasoning is read from both `reasoning` and `reasoning_content`. History replays it as `reasoning_content`, which vLLM ≥0.11 maps to both names for chat templates. | vLLM renamed the field across 0.11–0.16. |
| D-010 | Client-side `<think>` stripping applies to every model. Early content is held back only for reasoning models with thinking on, at most 1.5k chars, so a template-prefilled `<think>` (only `</think>` emitted) is detected without delaying normal streaming. | Thinking-2507 and Qwen3.5 templates prefill `<think>`; older vLLM parsers leave the thought in content. |
| D-011 | The fallback tool-call parser runs whenever tools were offered and no native calls came back. Streaming pauses at a recognized marker so raw markup never flashes in the UI. Unknown tool names are rejected to avoid false positives. | A misconfigured `--tool-call-parser` is the most common self-hosting failure. |
| D-012 | Token counts: `usage.prompt_tokens` is ground truth. Between responses we use a per-model chars-per-token ratio (EMA-calibrated from usage, persisted in `models_cache.json`) times a per-thread correction factor. vLLM `/tokenize` is used by Doctor. The HF `tokenizers` crate is **not** linked by default. | `tokenizers` pulls a large native dependency tree. Calibrated estimates plus overflow recovery (§10.5) already keep threads alive, as the soak test proves. `tokenizer_path` is reserved in config for a later feature flag. |
| D-013 | Context thresholds (`prune_at` 0.70, `compact_at` 0.85) are fractions of the **budget** (window − reserved output − margin), not of the raw window. | The budget is what a request can actually use. |
| D-014 | **Small-window mode:** models with a window ≤ 8,192 tokens get a compact base prompt (~250 tokens), a compact 7-tool set (shell, read, edit, write, plan, recall, read_output) and an AGENTS.md cap of ~12% of the window. | Otherwise the fixed prefix eats most of a 4k window. This is what makes the 4,096-token soak test pass. |
| D-015 | Approved memories are injected into the system prompt, not the post-compaction pinned block. | They change rarely, so this keeps the request prefix stable for vLLM prefix caching. They still survive every compaction, which is all PROMPT §10.4 requires. |
| D-016 | Git operations shell out to the `git` CLI instead of libgit2. | The user's config, hooks, credential helpers, LFS and worktree semantics behave exactly as in their terminal. |
| D-017 | The Windows sandbox defaults to a **write-restricted, Low-integrity token**. Writes need a custom Odex SID that gets inheritable ACEs (plus Low labels) on writable roots, and everything runs in a Job Object. AppContainer is available as `sandbox.windows_backend = "appcontainer"`. | Restricted tokens can read the user's toolchains (cargo, node, python under the profile), and AppContainer can't. The restricted token **does not isolate the network**: `status()` says so, and network-likely commands (execpolicy heuristics) ask for approval in `auto` mode. An unavailable backend → approval required, never silent. |
| D-018 | Agent PTY sessions (`exec_command`) use ConPTY via portable-pty only when unsandboxed (full access or approved). Sandboxed sessions use piped stdio under the sandbox. | portable-pty can't spawn with a custom token. |
| D-019 | Thread search and `recall` use SQLite FTS5 (BM25). Every history entry is indexed, with full tool output, when it's appended. | Built into the bundled SQLite, so no extra service. An embedding model can be added later via the `embedding` role. |
| D-020 | Browser-use logic lives once, in Rust (`browser-bridge`), behind a `CdpTransport`. Desktop transport = `browser/execute {action:"cdp"}` requests answered by `webContents.debugger`. Headless/exec transport = direct WebSocket to a CDP endpoint, or an auto-launched headless Edge/Chrome. | The same snapshot, ref and safety rules apply in the app and in tests. |
| D-021 | Rollouts are JSONL with typed lines. A full context `Checkpoint` is written after each prune or compaction, so replay doesn't re-run pruning. A crash leaves a partial line, which the writer terminates on reopen. | Append-only, replayable and crash-safe. |
| D-022 | Secrets (API keys, GitHub token) are encrypted by the desktop with `safeStorage` and handed to the engine in `initialize`, where they are held in memory only. The engine asks the desktop to persist new secrets via `secrets/store`. MCP OAuth tokens are the exception: the engine stores them in `~/.odex/mcp_tokens.json` itself, because the OAuth flow completes inside the engine. | Follows PROMPT §2. MCP tokens: noted as a known gap, to be moved behind `secrets/store` later. |
| D-023 | Goal mode continues by checking for the markers `GOAL: DONE`, `GOAL: BLOCKED: …` and `GOAL: CONTINUE` in the final message. Continuation turns are synthetic and appear as notices, not user bubbles. | Works with any model and needs no extra tool. Time and token budgets are enforced by the engine. |
| D-024 | `/review` runs a read-only turn, temporarily swapping in the `reviewer` model. The diff goes into hidden context and the final answer is parsed as JSON findings, leniently. | Tools are needed to inspect surrounding code, and those are incompatible with constrained decoding for the whole response. |
| D-025 | Subagents are one level deep (a subagent can't spawn more). The parent receives only the final report via `wait_agents`, and the UI shows a live card with identicon, nickname and diff stats. | Matches PROMPT §4 and keeps exploration out of the parent's context. |
| D-026 | Plugins are folders containing an `odex-plugin.toml` manifest. Trust is the user approving a content hash, and any file change requires re-review. | Plugins are local only, per PROMPT §1 (no marketplace). |
| D-027 | Automations use cron plus friendly phrases ("weekdays 09:00", "every 15m") via croner, instead of RFC 5545 RRULE. | PROMPT §8 says "cron or a friendly picker". |
| D-028 | Editor and diff: **CodeMirror 6** for file editing and a **custom diff renderer** for the review pane, with syntax highlighting from highlight.js. | The review pane needs per-hunk stage/revert buttons and inline comment threads interleaved with lines, which the Monaco diff editor makes awkward. CM6 is light and Vite-friendly. |
| D-029 | MCP OAuth, elicitation and the schema sanitizer are implemented in-house rather than with the `rmcp` SDK. | We control timeouts, Windows `.cmd` shims and the vLLM-safe schema flattening. |
| D-030 | The Stop hook can keep the agent going ("block" → a synthetic continuation turn), at most 3 times in a row. | Gives hook authors useful power while preventing infinite loops. |
